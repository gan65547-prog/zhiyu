### 任务 1.1：限流器改为 Redis 分布式实现

**文件**: `api/middleware/security.py` → `RateLimitMiddleware`

**背景**：当前使用 `defaultdict(list)` 内存存储，多 Worker 下各进程独立计数，限流形同虚设。

**方案细节**：
1. **复用已存在的 `RedisCache` 类**（`infrastructure/cache/redis.py`），`RegistrationRateLimitMiddleware` 已在用同一模式
2. 在 `__init__` 中注入 `RedisCache` 实例（可降级到内存）
3. 使用 Redis Sorted Set 实现 60 秒滑动窗口：

```python
# 伪代码 - Redis 滑动窗口
_KEY_PREFIX = "ratelimit:v2:"
async def _check_rate_limit(self, client_ip: str) -> bool:
    if self._redis:
        return await self._check_redis(client_ip)
    return self._check_memory(client_ip)  # 降级路径

async def _check_redis(self, client_ip: str) -> bool:
    key = f"{_KEY_PREFIX}{client_ip}"
    now = time.time()
    try:
        pipe = self._redis.pipeline()
        pipe.zremrangebyscore(key, 0, now - 60)   # 移除 60 秒前的记录
        pipe.zcard(key)                             # 计数
        pipe.expire(key, 120)                       # 重置 TTL
        _, count, _ = await pipe.execute()
        if count >= self.requests_per_minute:
            return False
        await self._redis.zadd(key, {now: now})     # 记录本次请求
        await self._redis.expire(key, 120)
        return True
    except Exception:
        return self._check_memory(client_ip)         # Redis 挂时降级到内存
```

4. **降级策略**：保留 `_check_memory` 作为 Redis 不可用/异常时的降级路径，通过 `try/except` 自动切换
5. 通过 `X-RateLimit-Remaining` 响应头返回剩余次数（基于当前窗口计数）

**工时**: 4h | **负责人**: 后端

### 任务 1.2：启用完整 CSRF 校验

**文件**: `api/middleware/security.py` → `CSRFMiddleware`

**背景**：当前 `/api` 在 `EXEMPT_PATHS` 中，非安全方法全部跳过；`_validate_token` 是死代码从未被调用；未设置 `csrf_token` Cookie（只设了响应头）。

**改动（后端）**:

1. **从 `EXEMPT_PATHS` 移除 `/api` 前缀** — 仅保留 `/health`、`/metrics` 等系统端点豁免
2. **安全方法（GET/HEAD/OPTIONS）返回时设置 `csrf_token` Cookie**：
```python
# 在 SAFE_METHODS 分支中，生成 token 并同时设置 Cookie + 响应头
csrf_token = await self._generate_or_get_token(request)
response.set_cookie(
    key="csrf_token",
    value=csrf_token,
    httponly=False,       # 前端 JS 需要读取
    samesite="lax",
    secure=False,          # 生产应设为 True（需 HTTPS）
    max_age=3600,
)
response.headers["X-CSRF-Token"] = csrf_token
```

3. **非安全方法（POST/PUT/PATCH/DELETE）实现真实 Token 比对**：
```python
if request.method not in self.SAFE_METHODS:
    header_token = request.headers.get("X-CSRF-Token", "")
    cookie_token = request.cookies.get("csrf_token", "")
    if not header_token or not cookie_token or header_token != cookie_token:
        raise HTTPException(
            status_code=status.HTTP_403_FORBIDDEN,
            detail="CSRF token mismatch or missing"
        )
```

4. **清理死代码**：删除 `_validate_token` 方法（第 205-208 行），其逻辑已被真实比对替代
5. **`_generate_or_get_token` 保持使用 `RedisCache`** 存储 token，兼容集群环境

**改动（前端）**:

- `frontend/src/api/auth.ts` / axios 拦截器中：
  - 从 Cookie 读取 `csrf_token`
  - 对非 GET 请求自动附加 `X-CSRF-Token` 请求头
```typescript
// axios 请求拦截器
api.interceptors.request.use((config) => {
    if (config.method && !['get', 'head', 'options'].includes(config.method)) {
        const csrfToken = getCookie('csrf_token');
        if (csrfToken) {
            config.headers['X-CSRF-Token'] = csrfToken;
        }
    }
    return config;
});
```

**工时**: 4h (后端 2-3h + 前端 1-2h) | **负责人**: 后端 + 前端

### 任务 1.4：数据库连接池生产调优

**文件**: `infrastructure/database/session.py`, `core/config.py`

**背景**：当前 PostgreSQL 路径只传了 `pool_size`、`max_overflow`、`pool_timeout` 三个参数；
缺少 `pool_pre_ping=True`（连接健康检测）和 `pool_recycle=3600`（连接超时回收）。

**改动**:

**1. `session.py`** — 给 `create_async_engine` 补充参数：
```python
# PostgreSQL 路径
engine = create_async_engine(
    settings.database.url,
    echo=settings.database.echo,
    pool_size=settings.database.pool_size,
    max_overflow=settings.database.max_overflow,
    pool_timeout=settings.database.pool_timeout,
    pool_pre_ping=settings.database.pool_pre_ping,     # 新增
    pool_recycle=settings.database.pool_recycle,        # 新增
)
```

**2. `core/config.py`** — `DatabaseConfig` 增加两个字段：
```python
class DatabaseConfig(BaseSettings):
    # ... 现有字段 ...
    pool_pre_ping: bool = Field(True, env="DB_POOL_PRE_PING")
    pool_recycle: int = Field(3600, env="DB_POOL_RECYCLE")
```

**3. Web/Worker 独立配置** — 因引擎是模块级单例，通过不同环境变量区分：

| 进程 | 环境变量 | 建议值 |
|------|----------|--------|
| Web | `DB_POOL_SIZE` | 20 |
| Web | `DB_MAX_OVERFLOW` | 10 |
| Worker | `DB_POOL_SIZE` | 5 |
| Worker | `DB_MAX_OVERFLOW` | 5 |

在 `docker-compose.yml` 和 `docker-compose.deploy.yml` 的 web / worker service 中分别设置不同值。

### 新增任务 3.5：5xx 全局异常处理器

**文件**: `main.py`

**背景**：当前只有 `QuotaExceededError` 的专用异常处理器，未捕获的 500 错误无统一响应格式。

**改动**：注册通用 `Exception` 处理器，统一返回 JSON 格式并记录结构化日志：
```python
@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    logger.error(
        f"Unhandled exception: {exc}",
        extra={"path": request.url.path, "method": request.method},
        exc_info=True
    )
    return JSONResponse(
        status_code=500,
        content={"detail": "Internal server error", "error_id": str(uuid.uuid4())}
    )
```

**工时**: 1h | **负责人**: 后端

```

  - 回退数据库迁移: alembic downgrade <上一个版本>
```

## 验收标准

| 检查项 | 标准 | 验证方式 |
|--------|------|----------|
| 速率限制 | Redis 分布式限流生效，多 Worker 共享计数 | 并发请求测试 |
| CSRF 保护 | API 路径 POST 请求需携带有效 Cookie+Header Token | 自动化安全测试 |
| 连接池 | `pool_pre_ping=True`, `pool_recycle=3600` 生效 | 检查 session.py 代码 |
| 依赖安全 | `pip-audit` 通过，无已知 CVE | CI 流水线 |
| API 测试 | 核心流程集成测试通过 | CI 流水线 |
| HTTPS | SSL 评级 A+ | SSL Labs 测试 |
| 迁移自动化 | CI 中迁移 + 回滚测试通过 | CI 流水线 |
| 优雅关闭 | `kill -TERM` 后完成进行中请求 | 手动验证 |
| 全局异常 | 未捕获异常返回统一 JSON 格式 | 手动注入异常测试 |
| 监控告警 | 5xx > 1% 触发告警 | 模拟故障验证 |
