# 项目实施计划

**项目名称：** Enterprise-RAG-V2 Phase 1 核心体验提升
**计划版本：** v1.0
**日期：** 2026-04-24
**预计周期：** 5 周

---

## 一、项目概述

### 1.1 目标

完成 Phase 1 四大模块的核心体验提升，使产品在文档理解、搜索质量、知识库管理和多模型支持方面达到竞品对标水平。

### 1.2 交付物

1. 增强版文档解析引擎（含 PDF 表格提取）
2. BM25 + 向量混合检索 + 结果溯源
3. 知识库首页仪表盘 + 全局搜索
4. 通用 OpenAI API 兼容层（≥3 模型）
5. 租户使用统计看板

### 1.3 关键里程碑

| 里程碑 | 时间 | 交付内容 |
|:------|:----:|---------|
| M1：技术选型完成 | Day 2 | 文档解析引擎选型确定 |
| M2：检索质量可达标 | Day 12 | 混合检索 + Reranker 集成完成，召回率 > 90% |
| M3：核心功能集成 | Day 22 | 文档解析 + 混合检索 + 多模型全部集成 |
| M4：前端交付 | Day 30 | 知识库首页 + 全局搜索 + 溯源 + 模型切换 UI |
| M5：验收测试 | Day 35 | 全功能验收 |

## 五、风险管理

### 5.1 风险登记册

| 风险 ID | 描述 | 概率 | 影响 | 应对策略 |
|:-------|:----|:----:|:----:|---------|
| R1 | MinerU 集成复杂度超出预期 | 中 | 高 | 备选 Docling；备选方案：仅做表格提取不做版面还原 |
| R2 | BGE-Reranker 模型在 CPU 上推理过慢 | 高 | 中 | 缩小 rerank 候选集（top 10）；fallback 到 SimpleReranker |
| R3 | Qdrant hybrid search 性能不达标 | 低 | 高 | 降级为纯向量检索 + 服务端 BM25 融合 |
| R4 | 前端改造量超出预估 | 中 | 中 | 先做 MVP（关键页面），非核心 UI 延后 |
| R5 | 文档解析 + 检索全链路延迟过高 | 中 | 高 | 增加缓存层，异步处理大型文档 |

### 5.2 应对预案

```
R1（MinerU 太复杂）：
  Day 2 选型结束时，如果 MinerU 集成成本 > 3 天 → 切换 Docling
  Day 7 如果 Docling 中文效果不达标 → 退回到 PyPDF2 + Camelot（仅表格提取）

R2（Reranker 性能问题）：
  BGE-Reranker CPU 模式：15 个候选的 rerank 延迟测试
  如果 > 500ms → 候选集缩小到 10
  如果 > 1s → 用 Cohere Rerank API（2000 次/月免费）

R3（Qdrant hybrid）：
  先做 RRF 模式（Qdrant 原生支持），不做 Weighted Sum
  如果混合检索比纯向量还慢 → 回退纯向量 + 应用层 BM25 加权
```

## 九、附录

### 9.1 技术选型评估要点

**MinerU（PDF-Extract-Kit）**
- 优点：中文效果最好、表格提取强、开源
- 缺点：依赖 GPU、部署较复杂、PyTorch 生态
- 适合：对中文 PDF 解析质量要求高的场景

**Docling（IBM）**
- 优点：多格式统一（PDF/DOCX/PPTX）、轻量、MIT 协议
- 缺点：中文效果中等、表格提取不如 MinerU
- 适合：需要多格式统一处理的场景

### 9.2 测试集构建指南

```
测试集格式（JSONL）：

{"query": "2023年公司营收是多少？", 
 "expected_answer": "1.2亿元",
 "source_doc": "2023年报.pdf",
 "category": "finance"}

{"query": "离职需要提前多久申请？",
 "expected_answer": "正式员工需提前30天",
 "source_doc": "员工手册.pdf",
 "category": "hr"}

分类覆盖：
- 财务数据（表格查询）
- 人事政策（文本查询）
- 技术文档（专业术语）
- 产品说明（多栏排版）
```

### 9.3 性能基准测试方案

```
测试环境：4C8G + GPU（如有）
测试工具：locust（并发） + 自定义脚本（延迟）

场景 1：文档解析
  10 份 PDF（含表格），记录处理时间和提取准确率

场景 2：混合检索
  100 个查询，记录 P50/P95/P99 延迟

场景 3：并发搜索
  10/50/100 并发用户，持续 5 分钟
  记录吞吐量 + 错误率
```
