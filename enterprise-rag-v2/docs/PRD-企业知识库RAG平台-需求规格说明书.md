## 1. 产品概述

### 1.1 产品定位

企业级私有化 AI 知识库平台——支持多租户、安全合规、开箱即用，让企业将内部文档快速转化为可检索、可问答的智能知识资产。

### 1.2 产品愿景

> 成为企业在私有化部署场景下的首选知识库平台——比 Dify 更专注知识库，比 RAGFlow 更懂企业。

### 1.3 目标用户

- **企业知识管理员** — 管理知识库内容、用户权限、使用情况
- **企业员工** — 搜索知识、与知识库对话
- **企业 IT 管理员** — 部署、运维、集成
- **SaaS 服务商** — 基于多租户为客户提供知识库服务

### 1.4 核心指标（OKR）

| 指标 | 当前 | Phase 1 目标 | 衡量方式 |
|:----|:---:|:-----------:|---------|
| 文档检索召回率 | 待评估 | > 90% | 测试集评估 |
| PDF 表格内容可检索 | ❌ | ✅ | 手动验证 10 份含表格 PDF |
| 支持 LLM 数量 | 2 | ≥ 3 | 计数 |
| 知识库搜索到结果时间 | 待评估 | < 2s（P95） | APM 监控 |
| 用户满意度（搜索结果） | 待评估 | > 4/5 | 内测用户反馈评分 |

## 3. 功能需求详述

### 3.1 EPIC 1：文档知识化

#### F-101 增强版 PDF 解析

| 字段 | 内容 |
|:----|------|
| **ID** | F-101 |
| **标题** | 增强版 PDF 文档解析 |
| **优先级** | P0 |
| **工作量评估** | 5 人天 |
| **依赖** | 无 |

**需求描述：**

当前基于 PyPDF2 的 PDF 解析无法正确处理以下场景：
- 包含表格的 PDF（表格数据丢失或混乱）
- 多栏排版（文字顺序错乱）
- 扫描件（无文本层）
- 页眉/页脚干扰

**详细要求：**

1. **基础文本提取改进**
   - 替换 PyPDF2 为更强解析引擎（MinerU 或 Docling）
   - 保留段落结构、标题层级、列表格式
   - 输出为 Markdown 格式的纯文本

2. **表格提取**
   - 识别 PDF 中的表格区域
   - 提取表格数据为结构化格式（Markdown 表格）
   - 表格内容必须可被召回（即搜索"2023年营收 1.2亿"可以找到表格中的对应行）
   - 支持：有边框表格、无边框表格、合并单元格

3. **版面还原**
   - 多栏文本按阅读顺序拼接（左→右、上→下）
   - 去除页眉、页脚、页码干扰
   - 保留标题层级（H1 → H2 → H3）

4. **扫描件 OCR**（P2，可延后）
   - 自动检测 PDF 是否有文本层
   - 无文本层时自动触发 OCR
   - 中文 OCR 准确率 > 95%

**验收标准：**
- [ ] 10 份含表格的 PDF，至少 8 份的表格内容被正确提取
- [ ] 双栏排版的 PDF，阅读顺序正确
- [ ] 表格中的数字可被搜索到
- [ ] 处理速度 < 30 秒/100 页（不含 OCR）

### 3.2 EPIC 2：智能检索

#### F-201 混合检索

| 字段 | 内容 |
|:----|------|
| **ID** | F-201 |
| **标题** | BM25 + 向量混合检索 |
| **优先级** | P0 |
| **工作量评估** | 2 人天 |
| **依赖** | 无 |

**需求描述：**

当前仅使用向量检索（余弦相似度），对精确关键词匹配不敏感。需要引入 BM25 全文检索，构成混合检索。

**详细要求：**

1. **BM25 全文检索**
   - 利用 Qdrant 的 `hybrid` 查询能力（即 `query` + `query_vector` 双路检索）
   - BM25 索引基于文档分块后的文本内容

2. **混合策略**
   - 支持两种融合模式：
     - `RRF`（Reciprocal Rank Fusion）—— 默认，无需调参
     - `Weighted Sum`—— 可配向量权重 vs 关键词权重
   - 默认权重：向量 0.7，BM25 0.3
   - 可在知识库级别配置

3. **检索参数可配置**
   - top_k（默认 5）
   - score_threshold（默认 0.0）
   - 至少返回 1 条结果（除非完全没有匹配）

**验收标准：**
- [ ] 搜索"2023年营收 1.2亿"可匹配到含表格的文档
- [ ] 搜索"离职流程"可匹配到 HR 文档中的相关段落
- [ ] RRF 模式在测试集上召回率 > BM25 单独或 向量单独
- [ ] 可在线切换混合策略

#### F-202 Reranker 优化

| 字段 | 内容 |
|:----|------|
| **ID** | F-202 |
| **标题** | Reranker 重排序优化 |
| **优先级** | P1 |
| **工作量评估** | 1 人天 |
| **依赖** | F-201 |

**需求描述：**

当前 SimpleReranker 只做基础打分，需要替换为语义级 Reranker。

**详细要求：**

1. **Reranker 集成**
   - 接入 BGE-Reranker-V2-M3（本地部署，免费）
   - 或 Cohere Rerank API（云端，付费）
   - 通过配置切换

2. **Rerank 策略**
   - 先 BM25 + Vector 混合检索取 top_k × 3 候选
   - Reranker 重排序后取 top_k
   - Rerank 超时控制（< 500ms）

**验收标准：**
- [ ] 引入 Reranker 后，排序质量在测试集上提升 10%+（NDCG@5）
- [ ] Rerank 延迟 < 500ms（top 15 候选）
- [ ] 支持本地和云端 Reranker 切换

## 7. 开放问题

以下问题需要进一步确认：

| 问题 | 影响 | 建议 |
|:----|:----|:----|
| 目标客户是哪种企业？ | 功能优先级 | 假设：中小型企业 + 中大型企业部门级 |
| 私有化部署 vs SaaS 占比？ | 部署策略 | 假设：70% 私有化，30% SaaS |
| 是否需要对接国产信创环境？ | 技术选型 | 假设：P2，先不做 |
| 当前前端框架是否满足仪表盘需求？ | 开发工作量 | 假设：Vue 3 + 组件库足够 |
| 文档解析精度是否可以接受部分失败？ | 用户体验设计 | 假设：部分失败可接受，但需要清晰提示 |
