# 数据库迁移核心业务流程详解

## 一、迁移框架概述

本项目采用 **Alembic** 作为数据库迁移框架，位于 `alembic/` 目录。Alembic 是 SQLAlchemy 官方推荐的数据库迁移工具，支持：
- 增量迁移（按版本顺序执行）
- 幂等性设计（重复执行不出错）
- 回滚支持
- 多数据库支持（PostgreSQL、SQLite）

### 1.1 核心目录结构

```
alembic/
├── env.py              # Alembic 配置文件，定义数据库连接和模型元数据
├── script.py.mako      # 迁移脚本模板
├── README.md           # 使用说明
└── versions/           # 迁移脚本目录（按时间顺序）
    ├── 001_initial_schema.py
    ├── 002_add_epub_document_type.py
    ├── ...
    └── 016_add_document_copy_status.py
```

## 三、核心业务流程

### 3.1 冷启动流程（首次部署）

```
┌─────────────────────────────────────────────────────────────┐
│                    冷启动迁移流程                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 执行 run-migrations.sh                                   │
│     ↓                                                       │
│  2. 检查 DATABASE_URL 环境变量                               │
│     ↓                                                       │
│  3. 转换数据库 URL                                           │
│     ├─ postgresql+asyncpg → postgresql+psycopg2             │
│     └─ sqlite+aiosqlite → sqlite                            │
│     ↓                                                       │
│  4. 检查 alembic_version 和 users 表是否存在                 │
│     ↓                                                       │
│  5. 若只有 alembic_version 无 users：删除并重新初始化        │
│     ↓                                                       │
│  6. 执行 alembic upgrade 001_initial_schema                  │
│     ↓                                                       │
│  7. 扩宽 alembic_version.version_num 到 VARCHAR(128)        │
│     ↓                                                       │
│  8. 执行 alembic upgrade head（执行所有剩余迁移）             │
│     ↓                                                       │
│  9. 迁移完成                                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 增量迁移流程（非首次部署）

```
┌─────────────────────────────────────────────────────────────┐
│                    增量迁移流程                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 执行 run-migrations.sh                                   │
│     ↓                                                       │

│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 幂等性保障

所有迁移脚本都实现了幂等性设计：

```python
# 示例：008_add_ops_center_tables.py
def upgrade():
    inspector = inspect(bind)
    existing_tables = inspector.get_table_names()

    if 'ops_users' not in existing_tables:  # 只在表不存在时创建
        op.create_table("ops_users", ...)

    if 'ops_roles' not in existing_tables:
        op.create_table("ops_roles", ...)

    # 数据插入也做幂等处理
    result = bind.execute(sa_text("SELECT COUNT(*) FROM ops_roles"))
    if result.scalar() == 0:  # 只在无数据时插入
        bind.execute(sa_text("INSERT INTO ops_roles ..."))
```

## 四、迁移执行脚本

### 4.1 run-migrations.sh（容器启动时执行）

路径：`scripts/container/run-migrations.sh`

核心逻辑：
```bash
# 1. 检查数据库完整性
python3 - <<'PYEOF'
    inspector = inspect(engine)
    has_alembic_table = inspector.has_table("alembic_version")
    has_users_table = inspector.has_table("users")

    # 如果只有 alembic_version 无 schema，删除重建
    if has_alembic_table and not has_users_table:
        conn.execute(text("DROP TABLE alembic_version"))
PYEOF

# 2. 升级到第一个迁移
python3 -m alembic upgrade 001_initial_schema

# 3. 扩宽版本号列
ALTER TABLE alembic_version ALTER COLUMN version_num TYPE VARCHAR(128)

# 4. 执行所有迁移
python3 -m alembic upgrade head
```

### 4.2 verify-migrations.sh（验证脚本）

路径：`scripts/verify-migrations.sh`

测试用例：
| 测试名称 | 测试内容 |
|----------|----------|
| 冷启动测试 | 在全新数据库上执行所有迁移 |
| 幂等性测试 | 重复执行迁移，验证无变化 |
| 完整周期测试 | downgrade → upgrade 完整循环 |
| 数据完整性测试 | 验证表结构和列完整性 |

## 六、枚举类型定义

### 6.1 PostgreSQL 枚举 vs ORM 枚举

项目采用了 **VARCHAR + CheckConstraint** 而非原生 PostgreSQL ENUM 的设计：

```python
# models.py 中定义
class OpsQuotaDimension(str, enum.Enum):
    USERS = "users"
    DOCUMENTS = "documents"
    STORAGE_MB = "storage_mb"
    API_CALLS_MONTHLY = "api_calls_monthly"
    CHAT_MESSAGES_MONTHLY = "chat_messages_monthly"
    WORKSPACES = "workspaces"

# 迁移中使用 VARCHAR + CheckConstraint
sa.Column("dimension", sa.String(50), nullable=False)
sa.CheckConstraint(
    "dimension IN ('users', 'documents', 'storage_mb', ...)",
    name="chk_quota_override_dimension"
)
```

### 6.2 枚举修复脚本

路径：`scripts/deploy/fix_opsquotadimension_enum.sql`

```sql
-- 背景：生产环境手动创建的 ENUM 类型缺少枚举值
-- 修复方法：直接在 PostgreSQL 中添加枚举值

-- 1. 查看当前枚举值
SELECT enumlabel FROM pg_enum
WHERE enumtypid = 'opsquotadimension'::regtype;

-- 2. 添加缺失值
ALTER TYPE opsquotadimension ADD VALUE 'api_calls_monthly';
ALTER TYPE opsquotadimension ADD VALUE 'chat_messages_monthly';
```

## 七、多数据库支持

### 7.1 数据库 URL 转换

```python
# env.py 中的 URL 转换逻辑
if db_url.startswith("sqlite+aiosqlite"):
    db_url = db_url.replace("sqlite+aiosqlite", "sqlite")
elif db_url.startswith("postgresql+asyncpg"):
    db_url = db_url.replace("postgresql+asyncpg", "postgresql+psycopg2", 1)
```

### 7.2 UUID 类型适配

```python
# PostgreSQL 使用原生 UUID 类型
id_column = sa.Column('id', postgresql.UUID(as_uuid=True),
    primary_key=True,
    server_default=sa.text('uuid_generate_v4()'))

# SQLite 使用 String(36) 存储 UUID
id_column = sa.Column('id', sa.String(36), primary_key=True)
```

## 八、部署注意事项

### 8.1 生产环境迁移要点

1. **幂等性优先**：所有迁移脚本必须支持重复执行
2. **向后兼容**：新增字段必须有默认值或允许 NULL
3. **索引命名**：避免与历史索引名冲突
4. **枚举处理**：优先使用 VARCHAR + CheckConstraint
5. **数据迁移**：重要数据变更先备份再执行

### 8.2 迁移执行顺序

```
1. 开发环境：alembic upgrade head
2. 测试环境：verify-migrations.sh 验证
3. 预发布：检查迁移日志
4. 生产发布：按顺序执行，监控错误
```

## 十、常见问题处理

### 10.1 迁移版本号过长

**问题**：Alembic 默认版本号长度为 32 字符，但本项目迁移 ID 较长。

**解决**：迁移 012 执行列宽扩展：
```sql
ALTER TABLE alembic_version ALTER COLUMN version_num TYPE VARCHAR(128)
```

### 10.2 PostgreSQL 枚举与 ORM 不一致

**问题**：生产环境手动创建的 ENUM 类型与 ORM 定义不一致。

**解决**：使用 `fix_opsquotadimension_enum.sql` 修复枚举值。

### 10.3 冷启动失败

**问题**：数据库存在 alembic_version 但 schema 不完整。

**解决**：run-migrations.sh 会自动检测并删除不完整的 alembic_version 表重新初始化。
