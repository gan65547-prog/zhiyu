# 多租户系统架构详解

## 一、核心概念

### 1.1 现实生活中的类比

假设你有一家公司叫 **"ABC科技公司"**：

```
🏢 ABC科技公司（这就是一个 TENANT - 租户）
    │
    ├── 👨‍💼 张三（USER - 用户）
    ├── 👩‍💼 李四（USER - 用户）
    └── 👨‍💻 王五（USER - 用户）
        │
        ├── 📁 "产品部"（WORKSPACE - 工作空间）
        │     ├── 张三（OWNER - 所有者）
        │     ├── 李四（ADMIN - 管理员）
        │     └── 王五（MEMBER - 成员）
        │
        └── 📁 "研发部"（WORKSPACE - 工作空间）
              ├── 李四（OWNER - 所有者）
              ├── 王五（ADMIN - 管理员）
              └── 张三（VIEWER - 查看者）
```

---

## 二、三者关系的核心要点

### 2.1 TENANT（租户）- 最高层级的组织
- 就像上面的 **"ABC科技公司"**
- 一个租户就是一个独立的企业/组织
- 租户拥有自己的所有数据、用户、工作空间、知识库

### 2.2 USER（用户）- 属于某个租户的人
- 就像 **张三、李四、王五**
- **用户属于租户**，不属于工作空间
- 一个用户可以加入同一个租户下的多个工作空间

### 2.3 WORKSPACE（工作空间）- 租户下的一个项目/部门
- 就像 **"产品部"、"研发部"**
- **工作空间属于租户**
- 工作空间里可以有多个用户作为成员

### 2.4 ROLE（角色）- 用户在某个工作空间里的身份
- **角色不属于用户，也不属于工作空间**
- **角色是"用户-工作空间"这个关联关系的属性**
- 同一个用户在不同工作空间可以有不同角色！

## 三、数据库表结构

### 3.1 表1：`users`（用户表）- 用户属于租户

| id | tenant_id | username | email |
|----|-----------|----------|-------|
| u1 | t1        | 张三     | zhangsan@abc.com |
| u2 | t1        | 李四     | lisi@abc.com |
| u3 | t1        | 王五     | wangwu@abc.com |

**关键点**：`tenant_id` 字段表明用户属于哪个租户

---

### 3.2 表2：`workspaces`（工作空间表）- 工作空间属于租户

| id | tenant_id | name |
|----|-----------|------|
| w1 | t1        | 产品部 |
| w2 | t1        | 研发部 |

**关键点**：`tenant_id` 字段表明工作空间属于哪个租户

---

### 3.3 表3：`workspace_members`（工作空间成员表）- 这是关联表！

| id | workspace_id | user_id | role |
|----|--------------|---------|------|
| m1 | w1           | u1      | owner |
| m2 | w1           | u2      | admin |
| m3 | w1           | u3      | member |
| m4 | w2           | u2      | owner |
| m5 | w2           | u3      | admin |
| m6 | w2           | u1      | viewer |

**这是最关键的表！** 解释：
- `workspace_id` + `user_id` 确定了"谁在哪个工作空间里"
- `role` 字段就是这个人在这个工作空间里的角色

## 四、具体角色例子

### 4.1 看张三（user_id = u1）的情况：

| 工作空间 | 角色 | 权限 |
|---------|------|------|
| 产品部（w1） | **OWNER** | 可以管理产品部的一切 |
| 研发部（w2） | **VIEWER** | 只能看研发部的内容，不能改 |

### 4.2 看李四（user_id = u2）的情况：

| 工作空间 | 角色 | 权限 |
|---------|------|------|
| 产品部（w1） | **ADMIN** | 可以管理产品部的成员和资源 |
| 研发部（w2） | **OWNER** | 可以管理研发部的一切 |

## 五、角色权限体系

### 5.1 角色定义

```python
class WorkspaceRole(str, enum.Enum):
    """工作空间角色"""
    OWNER = "owner"      # 所有者 - 最高权限
    ADMIN = "admin"      # 管理员 - 可以管理成员和资源
    MEMBER = "member"    # 成员 - 可以创建和编辑资源
    VIEWER = "viewer"    # 查看者 - 只能查看，不能编辑
```

### 5.2 角色权限矩阵

## 七、一句话总结

- **租户** 是公司
- **用户** 是公司员工
- **工作空间** 是公司里的部门/项目组
- **角色** 是员工在某个部门里的职位（经理、组员等）

**同一个员工可以在不同部门有不同职位！**
