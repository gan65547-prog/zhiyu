# AI 工作台系统实施基线

> **状态**：当前技术口径（2026-08-05）  
> **产品基线**：[AI 工作台产品详细落地方案](../design/AI工作台产品详细落地方案-v1.md)  
> **事实优先级**：运行代码与迁移 > 自动化测试 > 本文档 > 历史归档。

## 1. 当前系统边界

项目以 `enterprise-rag-v2` 为租户侧业务服务，以 `ops-center` 为独立运维控制面。现有生产底座负责认证、多租户、工作空间、数据集、文档处理、向量检索、对话、异步任务、监控和备份；AI 工作台在此基础上新增素材、结构化知识、研究和 Agent 协同能力。

| 层级 | 当前责任 | 主要事实源 |
|---|---|---|
| 租户侧 API | 认证、工作空间、数据集、文档、对话和业务能力 | `enterprise-rag-v2/api/`、`services/` |
| 异步处理 | 文档解析、切分、向量化、模板复制及重试 | `enterprise-rag-v2/infrastructure/queue/` |
| 数据与检索 | PostgreSQL 业务数据、Redis 缓存/队列、Qdrant 向量检索、对象存储文件 | `infrastructure/`、Alembic 与 Compose |
| 运维控制面 | 租户、配额、订阅、审计、重建索引等内部运维动作 | `ops-center/` 与 `/internal/admin/*` |
| AI 工作台增量 | 素材、知识卡片/Wiki、研究项目/运行/来源、Agent 运行与内容工作流 | 主方案 §26；未实现部分按 P0/P1 分期 |

## 2. 不可违反的边界

1. **租户隔离优先**：所有资源必须从当前用户、工作空间和租户关系校验，不信任客户端传入的资源 ID。
2. **单一知识入口**：上传、URL 抓取和后续连接器统一沉淀为素材，再进入现有文档/RAG 管道；不得为研究模块另建绕过权限的索引链路。
3. **研究可追溯**：研究结论必须关联来源、抓取时间、哈希、版本和审核状态；外部抓取须经 SSRF 防护、限速和许可策略。
4. **异步任务可恢复**：长耗时工作使用现有任务队列，具备任务状态、幂等键、重试、取消和失败可见性。
5. **运维面隔离**：`ops-center` 只使用受内部密钥、来源白名单和审计保护的内部接口，不能把高权限能力暴露给租户侧。
6. **上线证据优先**：发布必须通过发布 Runbook 的 Go/No-Go 条件；文档中的历史“完成”结论不能代替测试、备份恢复和回滚演练证据。

## 3. 分期实现

| 阶段 | 交付 | 依赖/验收 |
|---|---|---|
| P0 | 素材统一入口、现有 Dataset/RAG 接入、知识卡片/Wiki 的人工确认、来源引用与最小任务编排 | 复用现有 RAG；必须完成隔离、审计、异步恢复与核心链路回归 |
| P1 | 研究项目/运行/来源、可配置研究模板、连接器、评审工作流 | 先验证 P0 数据模型与来源治理 |
| P2 | 高级内容生产、跨系统自动化和指标闭环 | 在合规、成本和运维指标稳定后推进 |

详细数据模型、API、数据迁移和验收门禁只在主方案中维护；本文不复制字段或接口，以避免产生第二个技术方案。

## 4. 变更落点

| 变更类型 | 必须更新 |
|---|---|
| 产品范围、工作台数据模型、研究/Agent 方案 | AI 工作台主方案 |
| API 路由、请求/响应、错误码 | 路由/Schema/OpenAPI；必要时更新 `api/` 文档 |
| 表结构与迁移 | SQLAlchemy 模型和 Alembic；必要时更新数据库设计 |
| 环境变量、部署拓扑、备份、监控 | `deployment/` 对应指南与发布 Runbook |
| 可执行开发流程与质量门禁 | `development/` 对应指南 |

## 5. 当前不作为上线阻塞项的能力

长期记忆、复杂 Wiki 自动构建、全渠道连接器、自动内容发布和高级多 Agent 协作均不属于当前 P0 上线前置。它们必须在主方案中完成范围、数据治理和验收定义后才能进入开发，不能凭归档设计直接恢复实施。
